# Ora Desktop scaffold

Before treating the desktop client as releasable, complete the phased security and release checklist in [`../docs/desktop-release-checklist.md`](../docs/desktop-release-checklist.md).

This Tauri 2 Windows panel is an initial scaffold, not a supported release. The intended UI is restricted to time tracking, with app identity at the left of the header and theme, appearance, and user-menu controls at the right. Sign-in uses the dedicated `/api/desktop/login` endpoint with Ora account credentials; the older browser handoff remains available but is no longer needed by this UI. The timer should not include general navigation or recent-entry management. HTTP is allowed for remote LAN origins by explicit product decision, but traffic is unencrypted and should be restricted to a trusted network. Do not distribute this build: grants and sessions are process-local, desktop authentication and token persistence are not production-hardened, and localization, accessibility, production frontend packaging/build configuration, and installer integration remain incomplete.

For local testing, `npm run seed:desktop-demo` creates or resets `owner.demo@ora.local` / `OraDemoOwner2026!` and `user.demo@ora.local` / `OraDemoUser2026!`; never use these credentials in production. The desktop panel is not integrated into the Windows Ora installer or updater. Build prerequisites include Rust, the Tauri CLI, and the Windows WebView2 runtime; use the official Tauri setup guidance before attempting a local build. The current Tauri config is only a scaffold and does not yet define a production frontend build pipeline or restrictive CSP; do not use it to package/distribute a release. Remote LAN HTTP is supported by explicit deployment choice, but is unencrypted; use it only on a trusted network and prefer HTTPS. The manager update-status polling in the web shell stops after three consecutive request, HTTP, or response-parsing errors to avoid continued failed polling.
